# Oto
Revenue-recovery experiments for service businesses.

## Mission
Create measurable economic value for businesses, earn real revenue, and build portfolio-quality engineering. Autonomy is a means, not proof of value. Revenue is not guaranteed.

## Current phase
Phase 0: customer and problem validation. No live product, customers, bookings, or revenue claimed.
Canada is the initial geography. No vertical has been selected.
Working hypothesis: recover neglected inbound demand through one approved channel.
First milestones: a willing pilot customer, a verified recovered booking, and the first payment to Oto.

## Operating rules
- Separate verified facts, hypotheses, illustrative numbers, and customer evidence.
- No major feature until a pilot requirement justifies it.
- No spending, outreach, production deployment, or customer-data ingestion without approval.
- Owner-light is the goal, not zero upfront work. April prefers asynchronous sales; routine founder sales calls are not assumed.
- Do not promise results, invent testimonials, or present bookings as revenue.
- Prefer configuring an existing product when it solves the customer's problem economically.
- Keep credentials, prospect lists, transcripts, and customer records out of this public repository.

## Build gate
Begin the smallest pilot implementation only after a business confirms the problem, grants appropriate access, agrees to measurement, and accepts a defined commercial offer.
No agent framework, dashboard, or voice sales agent is required to validate demand.
